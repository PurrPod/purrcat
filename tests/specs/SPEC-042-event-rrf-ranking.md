# SPEC-042：事件检索用加权 RRF 顺序

## 背景

事件检索把向量与 BM25 两路候选交给 RRF 合并，但合并后又按向量余弦重新排序，
RRF 只影响候选集合、不影响最终顺序。评测显示三套中英文语料的候选池理想命中率
已达 95%+，损失集中在排序；保留融合顺序可同时提升 R@1/R@3/R@5。

## 行为

- 事件检索最终顺序由加权 RRF 决定：向量权重 0.5，BM25 权重 0.5，k=10。
- 每条事件的 `score` 仍是真实向量余弦，不改成 RRF 分数。
- 默认查询级拒识以候选中最高向量余弦为准，不受融合顺序影响。
- 经验、图谱检索的融合权重与 k 保持不变。

## 验收标准

- [ ] AC-1：向量首位与 BM25 首位不同时，最终顺序按加权 RRF 排列。
- [ ] AC-2：返回项的 `score` 等于该项的向量余弦。
- [ ] AC-3：融合首位余弦低于 0.80、但候选中存在 >=0.80 的事件时，查询不被误拒。
- [ ] AC-4：显式 `min_score` 仍逐条过滤，语义不变。

## 非目标

- 不改嵌入模型、候选池大小与 BM25 分词。
- 不引入 cross-encoder 重排。

## 测试矩阵

| 层级 | 位置 | 覆盖的验收标准 |
| --- | --- | --- |
| L0 | `tests/l0/test_event_score_threshold.py` | AC-1 ~ AC-4 |

## 风险与回滚

下游若自行按 `score` 重排会退回旧顺序；回滚只需恢复事件检索的最终排序与权重。
