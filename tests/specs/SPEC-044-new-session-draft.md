# SPEC-044：新会话草稿态落盘与延迟系统提示

## 背景

「新建会话」此前只是前端内存占位（`groupState.draft`）：不落盘、不进会话列表，首条消息才创建真实会话并立即构建系统提示词。用户切走或进程崩溃后无法解释残留，且空会话也会消耗提示词构建成本；重启后也没有显式标识可用来对账，只能靠 `messages_count == 0` 猜测。

## 行为

- 点击「新建会话」立即创建一个真实后端会话，出现在列表里，名称为「新建会话」，但在首条有效消息到达前不构建系统提示词。
- 草稿以 `meta.json` 的 `draft: true` 显式标识；清除后不再保留该字段，旧会话视为非草稿。
- 首条有效消息（输入框、宿主插件、ACP follow、sensor、timer）到达 Agent 的待处理队列后，只构建一次系统提示词：hook 空输出也视为完成；项目会话仍追加项目 `MEMORY.md` 块。之后永不重复构建。
- 草稿切走且仍未发送时，该会话被删除；Agent 忙碌时新建或切换返回 `busy`。
- 已在草稿态再次点击新建，停留在当前草稿，不产生第二条。
- 启动后台对账清理异常残留：仅删除 `draft == true` 且 `messages_count == 0` 的会话，跳过当前活跃会话；清理异常不阻断启动。
- 草稿窗口保留 header（标题「新会话」），隐藏会话 ID 与分支按钮，保留「最近会话」时钟入口。

## 验收标准

- [ ] AC-1：`save_session` 的 `draft=True/False/None` 分别写入、移除、保留 meta 与索引中的 `draft`。
- [ ] AC-2：`Agent(defer_system_prompt=True)` 空历史时不构建 system；`_checker` 首次消费只构建一次并把 system 放在 index 0。
- [ ] AC-3：首条消息构建完成后 `draft` 被清除；hook 空输出也算完成；项目块按会话归属追加。
- [ ] AC-4：后台对账只删空草稿，跳过 `skip_ids`，有消息的草稿与普通空历史会话保留。
- [ ] AC-5：宿主新建即落盘、切走删除空草稿、重复新建停留在当前草稿；启动时按列表 `draft` 恢复草稿态。

## 非目标

- 不改 ACP / sensor / timer 的注入路径。
- 不为草稿增加前端本地持久化。
- 不改压缩、分支、工具批次的既有顺序。

## 风险与回滚

- checkpoint 保存不能误清 `draft`，由 `draft=None` 保留语义与测试锁定。
- 删除草稿必须先 checkout 目标，否则后端会拒绝删除活跃会话。
- 回滚：移除 `draft` 参数/字段后，草稿退化为普通空会话，不影响其它会话。
