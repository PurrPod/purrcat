# SPEC-046 会话历史工具链聚合与任务耗时

## 背景

极简模式的会话历史把每次思考、每个工具调用都渲染成独立折叠气泡，长任务会堆出几十个同质化方块，
既看不清任务节奏，也浪费纵向空间。Bash 工具的结果摘要只有「成功 / 失败」，前端没有可用于展示命令
用途的输入参数，只能直接暴露整段命令。

## 行为

- 每个用户回合的正文按真实历史顺序平铺，不再把所有详情收进一个总抽屉：
  - 一级是固定的「logo 头像 + 任务已完成 / 正在执行中 + 耗时」，不参与展开收起；
  - 助手正文（包括中途回复）直接以正文级别渲染，保留其在历史中的位置；
  - 相邻正文之间的事件按段聚合出二级分组：
    - `参考了 N 个内容`：按注入位置成组，只有连续注入的参考才合并；跨过思考/工具则另起一组，不做去重；展开后每个参考项仍是收起的，再点开才看到具体内容；
    - `思考过程，执行 N 条命令，归档 N 个记忆…`：思考与工具合在一个二级统计里，展开后每一步仍可单独收起。
- 二级与三级默认收起；任务完成（思考态转空闲）时自动收起该回合已展开的细节。
- 工具步骤：
  - 文件编辑/创建默认收起为「已编辑/已创建 1 个文件」，展开后才显示文件类型图标、文件名蓝链与 +N/-M；
  - Bash 步骤标题展示「命令运行中 / 命令已执行 + snip」，标题本身是抽屉，点开才是伪终端；
  - `Memo` 步骤标题只展示「记忆归档 / 记忆检索」等结论，不暴露文件名/ID，点开查看归档的具体内容；
  - `Task` 按 action 区分：「查看了 N 张图片」展开后仅按行列出图片文件名；「派发子任务」展开查看指令、参数与结果；
  - `BrainStorm` 显示「更新了计划」，点开查看主计划步骤与子分支。
- 二级统计图标随实际内容变化（命令 / 文件改动 / 读取 / 搜索 / 记忆 / 纯思考）。
- Bash 工具 schema 新增可选参数 `snip`：一句话描述该命令的用途，供前端展示。

## 验收标准

- [ ] AC-1：Bash schema 暴露 `snip` 字符串参数且带用途说明，`command` 仍为必填。
- [ ] AC-2：一级状态行固定展示「任务已完成/正在执行中 + 耗时」，不可展开收起。
- [ ] AC-3：正文按真实顺序平铺；中间回复不再被收进「回复」折叠，也不再额外汇总到回合末尾。
- [ ] AC-4：参考内容按真实注入位置成组，连续注入才合并，不跨步骤聚合、不去重；思考与工具合并在一个二级统计里。
- [ ] AC-5：文件编辑默认收起，展开后显示类型图标、可点击蓝链与 +N/-M；Bash 用伪终端；Memo 点击展示归档内容。
- [ ] AC-6：任务完成后自动收起该回合已展开的二、三级细节。

## 非目标

- 不改变消息去重、分支切换、MCP App / GenUI 卡片的现有渲染逻辑。
- 不新增后端历史字段或接口；耗时由前端从用户事件的 `time` 推算。
- 不调整完整模式（非极简 UI）的聊天渲染。

## 风险与回滚

- `snip` 为可选参数：旧模型不传时前端回退到命令首行，不影响历史会话回放。
- 分组与折叠状态以消息序号为 key，轮询重建时保持展开状态；切换会话/分支会重置。
- 回滚：恢复按行渲染的折叠块，并删除 Bash schema 的 `snip` 字段。
