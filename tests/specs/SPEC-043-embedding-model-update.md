# SPEC-043：嵌入模型手动更新与向量库联动重建

## 背景

启动时 `ensure_embedding_model` 只要发现模型目录不是当前版本（例如旧 MiniLM 残留），
就自动重新下载并覆盖。用户无法选择时机，也没有「更新中」的状态反馈，进程中途退出
还可能留下写了一半的模型目录。

## 行为

- 启动检查只在模型目录缺失或为空（没有模型文件）时自动下载；已存在但版本不一致的
  目录不再自动替换，记忆设置页显示「嵌入模型过时」。
- 模型的下载与替换写入暂存目录 `embedding.next`，完整校验通过后再与 `embedding`
  原子换名；替换失败时回滚到旧目录，旧目录在成功后再删除。
- 更新操作 = 下载/替换模型 + 全量重建事件、经验、图谱向量；模型已是当前版本时只重建
  向量。
- 更新以后台任务执行，`GET /api/config/memory/embedding` 返回模型状态与任务状态；
  `POST /api/config/memory/embedding/update` 在任务运行中返回 409，不允许重复启动。
- 任务状态与阶段写入 `DATA_ROOT/embedding_update.json`；进程在更新中途退出后重启，
  该文件仍标记为运行中，接口返回 `interrupted`，设置页提示「上次更新未完成，请重试」。
- 任务按「下载 → 重建」推进，任一步失败都保留可重试状态：模型目录要么是新版本要么
  是旧版本，向量库因未写入模型标记而保持 stale。
- 替换模型后必须清理进程内的编码器缓存，确保后续检索使用新权重。

## 验收标准

- [ ] AC-1：模型目录缺失/为空时启动自动下载；目录内是旧版本时不下载、不覆盖、不删除。
- [ ] AC-2：安装先写暂存目录，校验完成后才替换目标目录；替换失败回滚旧目录。
- [ ] AC-3：模型过期时更新任务先替换模型再重建向量；模型已是最新时跳过下载只重建。
- [ ] AC-4：任务运行中重复调用启动接口返回 409，`GET` 返回 running 与当前阶段。
- [ ] AC-5：进程中断后重启，`GET` 返回 `interrupted=true`，再次启动更新可正常完成。
- [ ] AC-6：更新成功后三个 collection 写入当前模型标记，健康检查状态为 current。
- [ ] AC-7：替换模型后编码器缓存被清空，重建使用新权重编码。

## 非目标

- 不改变嵌入模型本身与向量维度。
- 不改变部署页安装其它依赖的行为。
- 不在前端拦截应用退出，只做任务标记与可重试的安全顺序。

## 风险与回滚

- 重建期间向量检索短暂不可用，与既有 `POST /memory/reindex` 一致。
- 回滚只需恢复启动自动替换逻辑与设置页按钮，模型与向量数据结构不变。
